# Ejercicio de Evaluación: Aplicación de COBIT 2019

## 1. Descripción del Ejercicio
Este ejercicio tiene como finalidad que demostréis vuestra capacidad para aplicar el marco **COBIT 2019** a situaciones reales de gobierno y gestión de TI. Trabajaréis en equipos de 4 personas, seleccionando un sistema o servicio de TI de los que habéis analizado en entregas anteriores de la asignatura y aplicando una selección representativa de procesos COBIT para diseñar su marco de gobierno y gestión.

## 2. Objetivos de Aprendizaje
Al completar este ejercicio, seréis capaces de:

*   **Comprender la estructura de COBIT 2019** y cómo sus dominios se interrelacionan para crear un sistema de gobierno coherente.
*   **Aplicar procesos específicos de COBIT** a un caso práctico, traduciendo conceptos teóricos en acciones concretas.
*   **Diseñar mecanismos de gobierno** que establezcan dirección, supervisión y evaluación sobre un servicio de TI.
*   **Definir controles y métricas** que permitan monitorizar el rendimiento y cumplimiento de un sistema.
*   **Trabajar colaborativamente** asumiendo roles especializados dentro de un equipo de gobierno de TI.

## 3. Selección de Procesos
COBIT 2019 comprende 40 procesos distribuidos en 5 dominios. Para este ejercicio, hemos seleccionado **12 procesos representativos** que cubren todo el ciclo de gobierno y gestión, permitiéndoos demostrar comprensión del marco sin que la extensión sea inabordable en el tiempo disponible.

### Criterios de Selección
Los procesos seleccionados cumplen los siguientes criterios: representan las funciones esenciales de cada dominio, son aplicables a cualquier sistema de información, permiten trabajo colaborativo con roles diferenciados, y cubren el ciclo completo desde la gobernanza hasta la monitorización.

### Procesos del Dominio EDM (Gobernanza)
| Proceso | Nombre | Descripción |
| :--- | :--- | :--- |
| **EDM01** | Marco de Gobierno | Establecer la estructura de gobierno del sistema: quién toma decisiones, cómo se supervisa y qué principios guían la gestión. |
| **EDM02** | Entrega de Beneficios | Definir qué valor debe aportar el sistema y cómo se medirá que efectivamente lo está entregando. |

### Procesos del Dominio APO (Planificación)
| Proceso | Nombre | Descripción |
| :--- | :--- | :--- |
| **APO02** | Gestionar la Estrategia | Alinear el sistema con los objetivos estratégicos de la organización universitaria. |
| **APO12** | Gestionar el Riesgo | Identificar y evaluar los riesgos del sistema, definiendo respuestas apropiadas. |
| **APO13** | Gestionar la Seguridad | Establecer las políticas y controles de seguridad de la información. |

### Procesos del Dominio BAI (Implementación)
| Proceso | Nombre | Descripción |
| :--- | :--- | :--- |
| **BAI02** | Gestionar Requisitos | Documentar los requisitos funcionales y no funcionales del sistema. |
| **BAI05** | Cambio Organizativo | Planificar cómo se gestionará la adopción del sistema por los usuarios. |
| **BAI06** | Gestionar Cambios TI | Definir el proceso de control de cambios técnicos en el sistema. |

### Procesos del Dominio DSS (Operaciones)
| Proceso | Nombre | Descripción |
| :--- | :--- | :--- |
| **DSS01** | Gestionar Operaciones | Describir las actividades operativas diarias para mantener el servicio. |
| **DSS02** | Gestionar Incidentes | Diseñar el proceso de atención a incidentes y peticiones de usuarios. |

### Procesos del Dominio MEA (Monitorización)
| Proceso | Nombre | Descripción |
| :--- | :--- | :--- |
| **MEA01** | Monitorizar Rendimiento | Definir métricas e indicadores para evaluar el funcionamiento del sistema. |
| **MEA03** | Gestionar Cumplimiento | Identificar requisitos normativos aplicables y cómo verificar su cumplimiento. |

## 4. Organización del Equipo
Cada equipo debe organizarse asignando roles especializados. Aunque cada miembro lidera unos procesos específicos, todos deben participar en la revisión y coherencia del trabajo completo. La integración de las diferentes partes es fundamental para la calificación.

### Roles y Responsabilidades
| Rol | Procesos Asignados | Responsabilidad Principal |
| :--- | :--- | :--- |
| **Responsable de Gobernanza** | EDM01, EDM02 | Coordina la coherencia global del marco de gobierno |
| **Responsable de Planificación** | APO02, APO12, APO13 | Asegura la alineación estratégica y gestión de riesgos |
| **Responsable de Implementación** | BAI02, BAI05, BAI06 | Define procesos de construcción y cambio |
| **Responsable de Operaciones** | DSS01, DSS02, MEA01, MEA03 | Define operación diaria y mecanismos de control |

### Nota sobre la Colaboración
Aunque cada rol tiene procesos asignados, la evaluación valorará especialmente la **coherencia e integración** del trabajo. Por ejemplo, los riesgos identificados en APO12 deben reflejarse en los controles de APO13, y las métricas de MEA01 deben medir los beneficios definidos en EDM02. Planificad sesiones de trabajo conjunto para asegurar esta integración.

## 5. Estructura del Entregable
El documento debe estructurarse siguiendo el esquema que se indica a continuación. La extensión orientativa es de **25-35 páginas**, sin contar anexos.

| Sección | Extensión | Contenido |
| :--- | :--- | :--- |
| **Portada e índice** | — | Identificación del equipo, roles asignados e índice de contenidos |
| **Resumen** | 1-2 págs. | Síntesis del sistema analizado y principales conclusiones del marco de gobierno propuesto |
| **Descripción del sistema** | 2-3 págs. | Contexto, objetivos, stakeholders y arquitectura general del sistema seleccionado |
| **Dominio EDM - Gobernanza** | 3-4 págs. | Estructura de gobierno, modelo de toma de decisiones, definición de valor y beneficios esperados |
| **Dominio APO - Planificación** | 4-5 págs. | Alineación estratégica, análisis de riesgos con matriz de evaluación, y política de seguridad |
| **Dominio BAI - Implementación** | 4-5 págs. | Catálogo de requisitos, plan de gestión del cambio organizativo y procedimiento de control de cambios técnicos |
| **Dominio DSS - Operaciones** | 3-4 págs. | Procedimientos operativos, proceso de gestión de incidentes con niveles de prioridad y SLAs |
| **Dominio MEA - Monitorización** | 3-4 págs. | Cuadro de mando con indicadores, umbrales y frecuencias; análisis de cumplimiento normativo aplicable |
| **Conclusiones y reflexión** | 1-2 págs. | Valoración de la aplicabilidad de COBIT al caso, dificultades encontradas y aprendizajes del equipo |
| **Anexos** | Variable | Diagramas, tablas detalladas, matrices completas u otros materiales de apoyo |

## 6. Rúbrica de Evaluación
La nota final será la suma ponderada de las puntuaciones obtenidas en cada criterio.

### Criterio 1: Comprensión de COBIT (20%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Demuestra comprensión profunda de los procesos, sus interrelaciones y su propósito. Aplica correctamente la terminología. |
| **Notable (70-89%)** | Comprende bien los procesos individuales y muestra entendimiento de las conexiones principales entre dominios. |
| **Aprobado (50-69%)** | Comprende los conceptos básicos de cada proceso pero no establece conexiones claras entre ellos. |
| **Insuficiente (<50%)** | Muestra comprensión superficial o errónea de los procesos. Confunde conceptos fundamentales. |

### Criterio 2: Aplicación Práctica (25%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Traduce cada proceso en acciones concretas, específicas y realistas. Ejemplos detallados y reflexivos. |
| **Notable (70-89%)** | La mayoría de procesos se aplican correctamente con ejemplos concretos. |
| **Aprobado (50-69%)** | Aplica los procesos de forma genérica, sin suficiente adaptación al contexto específico. |
| **Insuficiente (<50%)** | La aplicación es teórica o abstracta, sin conexión real con el sistema analizado. |

### Criterio 3: Coherencia e Integración (20%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Visión sistémica: riesgos reflejados en controles, beneficios en métricas, requisitos en operaciones. |
| **Notable (70-89%)** | Buena coherencia general con conexiones explícitas entre la mayoría de secciones. |
| **Aprobado (50-69%)** | Secciones relacionadas pero las conexiones son implícitas o poco desarrolladas. |
| **Insuficiente (<50%)** | Las secciones parecen trabajos independientes sin coherencia ni integración visible. |

### Criterio 4: Calidad Técnica (15%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Matrices de riesgo, SLAs, métricas y controles completos y técnicamente correctos. |
| **Notable (70-89%)** | Elementos técnicos correctos y razonables, con pequeños puntos de mejora. |
| **Aprobado (50-69%)** | Elementos técnicos básicos pero aceptables. Imprecisiones menores. |
| **Insuficiente (<50%)** | Elementos técnicos incorrectos, incompletos o falta de comprensión. |

### Criterio 5: Presentación y Comunicación (10%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Estructura excelente, redacción clara/profesional, uso efectivo de tablas y diagramas. |
| **Notable (70-89%)** | Buena estructura y redacción. Uso adecuado de elementos visuales. |
| **Aprobado (50-69%)** | Estructura aceptable aunque mejorable. Algunos problemas de redacción. |
| **Insuficiente (<50%)** | Documento desorganizado, difícil de seguir. |

### Criterio 6: Reflexión Crítica (10%)
| Nivel | Descripción |
| :--- | :--- |
| **Excelente (90-100%)** | Reflexión profunda sobre aplicabilidad, limitaciones, adaptaciones y aprendizajes significativos. |
| **Notable (70-89%)** | Buena reflexión que identifica fortalezas y debilidades de la aplicación del marco. |
| **Aprobado (50-69%)** | Reflexión superficial que menciona algunos aspectos sin profundizar. |
| **Insuficiente (<50%)** | Ausencia de reflexión o comentarios genéricos sin relación con la experiencia. |
